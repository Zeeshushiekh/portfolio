CASE STUDY 01 · HEALTHCARE WORKFLOWS

Child Immunization Module

Built the backend workflow connecting vaccine master configuration, newborn scheduling, due-dose notifications and vaccination administration records.

Delivered work

Problem & approach

Tracking each child's vaccination timeline requires consistent vaccine master data, schedule mapping and reliable records of which doses have been administered. I worked on the end-to-end module workflow to connect those stages inside the healthcare application.

Configuration establishes the vaccination rules. A newborn is mapped against the schedule, due doses can trigger notifications, and administered vaccines are recorded against the child in the database.

My implementation

  • Configured vaccine master data and newborn-to-vaccine schedule mapping.
  • Implemented logic supporting due-dose identification and notifications.
  • Handled recording of administered vaccinations for ongoing tracking.
  • Connected the workflow to application data and database operations.

REST APIs, Quartz Scheduling & Apache Airflow

Connecting external systems and keeping multiple databases synchronized as recurring processing needs grew.

Measured impact

CASE STUDY 04 · PERFORMANCE ENGINEERING

JMeter Findings to Production Fixes

Worked with EY performance engineers to investigate why application requests and database operations were slowing down.

Production engineering

Investigation

EY shared JMeter performance reports that highlighted slow workflows and requests. I collaborated on the subsequent application analysis, identifying issues spanning resource management, repeated API calls and expensive SQL operations.

Problems were evaluated at both application and database levels rather than treating every slowdown as a single query issue.

Fixes contributed to

  • Fixed database connections that were not being closed correctly in some applications.
  • Removed redundant API calls triggered within requests.
  • Worked on inefficient large-image storage or handling concerns.
  • Introduced or adjusted indexes and partitioning for relevant database workloads.
  • Improved date filtering by removing unnecessary column-side truncation functions in queries where applicable.
